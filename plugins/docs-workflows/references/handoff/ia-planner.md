# ia-planner Handoff Format

The input and output contract for `ia-planner`, read by the agent itself. Its input is the other half of `${CLAUDE_PLUGIN_ROOT}/references/handoff/docs-auditor.md`'s output: **`surfaces[]` and `unresolved[]` arrive verbatim from that block**, field for field, and nothing between the two agents reshapes them. The field names of a unit and of a tutorial candidate are `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/backlog-format.md` §1's; the page-`type` vocabulary, the four prioritisation signals and the churn guard are `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/coverage-model.md` §3 and §5's. Neither is restated here.

## Input

```yaml
surfaces:                              # docs-auditor's surfaces[], verbatim
  - id: order-placement
    kind: task
    title: "Place an order"
    roles: [customer, admin]
    evidence:
      - { repo: example-webapp, path: src/routes/orders/new.tsx }
    volatility: high                   # high | medium | low | unknown

audiences: [user, engineering]         # optional; both where the caller names none

unresolved:                            # optional; docs-auditor's unresolved[], verbatim — carried, never acted on
  - { theme: <verbatim>, source: <repo name, or "specs">, reason: <one line> }

existing_units:                        # optional; on a --refresh run, the units already in the backlog
  - { id: U-001, surface: order-placement, audience: user, type: how-to, priority: 1 }

existing_tutorial_candidates:          # optional; on a --refresh run, the candidates already in the backlog
  - { role: customer, journey: [order-placement, payment], picked: false, unit: null }
```

Refuse to run without a **non-empty** `surfaces[]`, and without both `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/coverage-model.md` and `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/backlog-format.md`. An empty `surfaces[]` is `docs-auditor`'s `NO_SURFACES`, which is the caller's to report rather than a plan for this agent to make; this agent is not dispatched on it.

**`surfaces[]` and the two reference files are evidence inputs; `audiences[]`, `unresolved[]`, `existing_units[]` and `existing_tutorial_candidates[]` are context inputs.** An unreadable evidence input is a hard stop and is never regenerated by other means; an unreadable context input degrades to absent and the degradation is recorded in `degraded[]`. The agent body states both tiers in full. **Not supplied and degraded are different states**: an initial run carries no `existing_units[]` and that is ordinary; a `--refresh` run whose `existing_units[]` would not read has lost its view of which cells are occupied and which ids are taken, and the caller must know which of the two it is before it writes.

**No `model_routing:` block is passed.** This agent's tier is pinned by its own frontmatter (`model: opus`), and nothing in the agent reads a field of that block.

**This agent never asks a question.** It has no user: there is no `choices:` array in its return, no escalation, and no field the operator answers. The one judgement reserved for a person — which journey a role should learn first — reaches them as a `tutorial_candidates[]` entry with `picked: false`, which they set by editing the backlog.

## Output

```yaml
status: OK | PARTIAL | NO_UNITS

units:                                 # exactly backlog-format.md §1's fields for a unit
  - id: U-001
    surface: order-placement           # always a surface id from the supplied surfaces[]; never null
    journey: []                        # always empty here — a journey belongs to the tutorial mint, which is /docs-audit --refresh's
    title: "Place an order"
    audience: user                     # user | engineering
    visibility: public                 # defaults from audience; a departure is explained in priority_reason
    type: how-to                       # coverage-model.md §3's vocabulary; never `tutorial`
    roles: [customer]
    priority: 1
    priority_reason: "blocks primary journey; 2 roles; evidence available"
    churn_adapted: false
    status: missing                    # always `missing` here
    page_path: null                    # always null here — no page exists yet
    walkthrough: null                  # always null here — nothing in this increment composes one
    evidence: []                       # always empty here — a unit's own evidence is written only on a surface: null unit
    blocked_by: []                     # always empty here

tutorial_candidates:                   # proposed, never picked
  - role: customer
    journey: [order-placement, payment, order-tracking]   # surface ids, in the order somebody would meet them
    rationale: "shortest path through the three highest-priority customer tasks"
    picked: false                      # always false here
    unit: null                         # always null here

unresolved:                            # the input's unresolved[], echoed verbatim
  - { theme: <verbatim>, source: <repo name, or "specs">, reason: <one line> }

degraded:                              # context inputs that were supplied and could not be read
  - input:  audiences | unresolved | existing_units | existing_tutorial_candidates
    reason: <one line>

notes: |
  <what the run's report needs and the blocks above do not carry: a surface that earned no unit
  and why; the type chosen for each `role` and `release` surface, with its reason, since §2 names
  a page shape for those two rather than a type; any `visibility` that departs from its audience
  default, with its reason; a role that got no candidate and why; a role whose existing candidate
  this run would have proposed a different journey for, with that journey named and nothing
  rewritten; and — where `existing_units` was not supplied — the fact that ids were minted from
  U-001 and cells were checked only within this return, so the caller must check both against the
  file before it writes.>
```

## Status codes

| Status | Meaning |
|---|---|
| `OK` | `units[]` is non-empty, every surface in `surfaces[]` was considered, and `degraded[]` is empty. A non-empty `unresolved[]` does **not** make a run `PARTIAL` — it is the input's finding, carried through, and this agent resolved nothing and lost nothing. |
| `PARTIAL` | `units[]` is non-empty **and** at least one of these holds: a context input degraded, or a surface could not be planned and was skipped — a `kind` outside `coverage-model.md` §2's seven, or a surface carrying an empty `evidence[]`, neither of which `docs-auditor` emits. `notes` names each one. |
| `NO_UNITS` | `units[]` is empty although `surfaces[]` was not. This is reachable and is not an error: `audiences: [engineering]` over a set of `task` and `concept` surfaces mints nothing, because those kinds feed user types. `notes` says which of the two it was — a filter that excluded everything, or surfaces that earned nothing — and `tutorial_candidates[]` may still be non-empty. |

**`tutorial_candidates[]` is independent of the status.** It can be empty on an `OK` run, where no role had a journey worth stringing together, and non-empty on a `NO_UNITS` one. It is never the reason a status is `PARTIAL`, because proposing no candidate is a judgement rather than a failure — `notes` carries the reason either way.
