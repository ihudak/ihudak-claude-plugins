# Rulings made while executing the BRD figures and appendices plan

Branch `iv-gu/brd-figures`. Plan `docs/superpowers/plans/2026-09-18-brd-figures-and-appendices.md`, spec `docs/superpowers/specs/2026-09-18-brd-figures-and-appendices-design.md`. Companion to `2026-09-22-brd-figures-execution-runs.md`, which records the verification runs.

## What a ruling is, and why they are here

The branch was executed with `superpowers:subagent-driven-development`, whose standing rule is that a running plan does not stop to ask: where the plan contradicted itself, where a review finding disagreed with the plan text, where an implementer hit a cap or an ambiguity, the controller decided, recorded the decision with what it would cost if wrong, and kept going. That trail lived in the branch's scratch ledger, which is deleted when the branch finishes — so it is copied here verbatim, in numeric order, because the shipped prose says what the release does and only this says why it says it. Where a ruling and the shipped text disagree, **the shipped text is the authority**: several rulings below were overturned by later evidence, and the overturning ruling is in the list too.

171 numbers were allocated and 170 are below. The exception is R100, a routing decision recorded in the ledger's narrative rather than as an entry of its own: *pass 7 reviewed — 0 Critical, 0 Important, 3 Minor — therefore pass 9's brief is written after pass 8 rather than beside it.*

## The ones worth a second look

Most of these settle wording. A few chose something a reader might want to revisit:

- **R73 is the one that governed the endgame**, and it corrects six earlier rulings (R51, R54–R58, R62, R71) that had routed pre-existing defects to the user as a decision. The zero-known-bugs policy had already decided it: every defect the verification runs surfaced was fixed on this branch, whether or not this branch introduced it. R132, R147 and R166 are later applications of the same rule, each reopening a batch that had already reported finished.
- **R69 and R97 disclose limits rather than fixing them**, each because the fix needs provenance the tree does not keep. They are recorded in the release's own changelog as costs, not left silent.
- **R121 rejected a recovery mechanism a reviewer proposed** and bought the recovery in the run's report instead. The reasoning is in the ruling; a future reader tempted by the same mechanism should read it before re-proposing.
- **R40 accepted a real cost to an operator**: a customer's heading quoted in plugin prose without its path now stops a package, and the repair is to write the path.
- **R68 changed how an ambiguous wikilink resolves** — a sibling file now wins where the vault holds another match, which is what the editor it imitates does.
- **R166 upgraded a finding to Critical** on the unrecoverable loss it caused, against a reviewer who offered the grade conditionally.
